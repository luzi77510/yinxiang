# 别人对你的第一印象测试网站完整开发提示词

使用方式：将本文件全文发送给网站开发 AI。附录已包含完整题库、评分映射和结果文案，可以独立使用。

方案依据：18 道题、P/G/M 三个维度、三个主结果、隐藏彩蛋、评分与同分规则、结果内容和主题配色沿用原产品文档。具体色值、视觉布局、技术选型、权限、接口和交互细节为本方案补充的实施建议。

以下为可直接复制的提示词正文。

---

请作为产品设计师和全栈开发工程师，为我制作一个中文网站《别人对你的第一印象测试》。请交付可以运行、可以完成完整测试、具有真实数据存储和后台管理能力的网站。附录是产品内容和评分配置来源；实现以下明确需求。

## 一 产品定位和交付范围

网站面向喜欢趣味测试和社交分享的年轻用户。核心体验是：进入首页 → 开始测试 → 完成 18 道情境单选题 → 获得第一印象称号和三维分数 → 阅读分析和建议 → 自愿生成分享海报或链接。

产品语气轻松、友善、有一点好奇感，评价采用“可能”“倾向于”等表述。明确说明这是娱乐性自我探索工具，结果来自用户自述的情境选择，不代表他人真实评价或专业心理测量结论。

内容使用简体中文。用户可以匿名完成测试，昵称为可选项。先交付完整测试和管理功能，好友对比、运营活动和更多结果类型列为后续扩展。

页面及路由建议：

| 页面 | 建议路由 | 主要任务 |
| --- | --- | --- |
| 首页 | `/` | 介绍测试，引导开始或继续答题 |
| 答题页 | `/test` | 一题一屏，保存答案和进度 |
| 个人结果页 | `/result/[id]` | 展示本次结果及完整分析，校验访问权限 |
| 公开分享页 | `/share/[token]` | 仅展示用户主动公开的结果摘要和测试入口 |
| 管理员登录 | `/admin/login` | 管理员身份认证 |
| 管理后台 | `/admin` | 统计、题库、结果、规则和版本管理 |
| 说明页面 | `/privacy`、`/about` | 隐私说明、测试说明及内容声明 |

## 二 网站整体视觉风格

### 1 视觉方向

采用“轻杂志排版 + 插画人格卡牌 + 轻微神秘感”的风格。页面以浅色为主，温柔、干净、有辨识度，让用户愿意完成答题并保存结果卡。

背景采用淡淡的纸张颗粒感和少量星点装饰，内容区留出充分空白。整体层次主要依靠排版、插画和卡片建立。大面积渐变、厚重发光和玻璃效果不作为主要视觉语言。

三种人格使用同一套原创形象语言：太阳代表亲和感，星光代表气场感，月亮或面纱代表神秘感。形象造型保持一致，通过颜色、表情和姿态区分，不能仅靠更换图标表达结果差异。可用 SVG 实现统一的简洁插画；装饰图不承担必需信息。

### 3 排版和组件

使用系统中文无衬线字体栈；如使用额外字体，优先本地托管并提供回退。桌面首页内容最大宽度约 1120px，答题内容约 680px，结果正文约 760px。移动端优先适配 375px 和 390px，并覆盖 320px 窄屏。

移动端左右留白 20px，正文 16px，行高约 1.7。首页标题移动端约 32px、桌面约 48px。卡片圆角 20px，按钮圆角 14px；阴影柔和，描边细。点击目标至少 44px，答题选项整块可点且最小高度约 64px。

动效以 150—300ms 的轻淡入、位移和状态反馈为主。结果揭晓可稍长，但可跳过，并支持系统减少动态效果偏好。

## 三 首页要求

首页以“让用户快速理解并开始测试”为目标。手机首屏必须看到标题、副标题、测试信息和开始按钮。

按以下顺序组织：

1. 顶部：简洁品牌标识和“测试说明”入口。管理后台通过独立地址访问。
2. 主标题：别人对你的第一印象测试。
3. 副标题：初次见面，你在别人眼里究竟是什么画风？
4. 引导文案：你以为自己很高冷，别人可能觉得你不好惹；你以为自己很普通，别人可能早就记住了你。18 道情境题，探索你的第一印象倾向。
5. 主视觉：三种人格形象错位组合成一组卡牌，分别露出“亲和系”“气场系”“神秘系”等短标签。
6. 测试信息：18 道题 / 预计 3 分钟 / 没有标准答案。
7. 主按钮“开始测试”，辅助文案“凭直觉选择，不用刻意美化自己”。
8. 简短说明三个维度分别代表什么，允许预览结果称号与形象，完整结果需完成答题后呈现。
9. 页脚展示娱乐属性说明、隐私说明和关于测试入口。

如检测到未完成且仍有效的答题草稿，主按钮显示“继续答题”，并提供“重新开始”次级操作。重新开始前说明将清除本地未完成答案。

首页采用浅背景、深文字和人格插画建立视觉重点，首次访问不弹出营销遮罩。公开人数、结果占比等数据如果展示，必须来自真实统计。

## 四 测试答题页要求

1. 固定 18 道题，每题 A/B/C/D 四个选项，单选。题目和选项严格使用附录。题目顺序沿用 Q1—Q18，评分维度代码只作为内部数据。
2. 页面顶部有返回入口、当前题号（例如 03/18）和整体进度条。进度按已完成题目数计算，并明确当前位置。
3. 一题一屏，题目清晰，四个选项纵向排列。选项使用字母、正文和选中标记；选中后显示主色描边、浅色底和勾选。
4. 点击后立即保存答案；改选覆盖旧答案。默认点击“下一题”后前进，方便用户核对和修改。
5. 未选择时“下一题”禁用；支持上一题，返回后恢复原选项。第一页不显示可用的上一题操作。
6. 最后一题按钮改为“查看我的第一印象”。提交前校验 18 道题完整且选项合法。
7. 本地保存当前题号、答案、测试会话和题库/规则版本；刷新后恢复。保存有效期可配置，默认 7 天。进行中的会话使用开始时绑定的配置版本。
8. 提交时显示明确加载状态，防止连续点击。网络失败可重试，已经保存的答案不丢失。同一会话重复提交返回已有结果，避免重复计数。
9. 结果计算完成后进入结果页。可以播放约 0.8—1.5 秒的揭晓过渡，加载文案使用“正在整理你的第一印象画像”，不虚构扫描他人评价等能力。
10. 键盘和屏幕阅读器可操作选项与按钮；焦点清晰。移动端底部按钮兼容安全区域，不遮挡最后一个选项。

## 五 评分算法和隐藏彩蛋

算法在独立模块实现。客户端可用于即时预览，正式记录由服务端根据答案重新计算，以服务端为准。业务规则不能散落在不同页面中。

### 1 维度和分数

- P：亲和感；对应“人间小太阳”。
- G：气场感；对应“自带主角光环”。
- M：神秘感；对应“神秘感狙击手”。
- 每题只增加一个维度的 1 分，原始分之和始终为 18，单维度范围 0—18。
- 每维度展示分数为 `Math.round(原始分 / 18 * 100)`，范围 0—100。分母固定为 18。
- 三个展示分数因各自四舍五入可能不恰好合计 100，保留真实换算值，不为凑整或美化形状修改分数。
- 分数表示本次选择在三个维度上的分布，不是人群排名、心理测量百分位或真实性概率。低分不代表缺点。

### 2 唯一主结果和同分规则

某维度严格最高时，直接返回对应结果。两维并列最高时，仅对并列的两个维度计票，第三维度的票不参与比较；必须读取指定题目的最终选项映射后的维度。

| 并列情况 | 参考题目 | 判定 |
| --- | --- | --- |
| P/G | Q5、Q10、Q15 | G 票数多于 P 则 G，否则 P |
| P/M | Q3、Q9、Q12 | M 票数多于 P 则 M，否则 P |
| G/M | Q6、Q14、Q18 | M 票数多于 G 则 M，否则 G |
| P/G/M | 三维完全相同 | 固定优先级 P > G > M，返回 P |

缺题、非法选项、配置缺失或非法维度应返回明确错误，不生成结果。合法答案必须获得唯一主结果；需要确定性兜底时，按最高分候选中的 P > G > M 处理，并记录异常。

### 3 附加标签

按四舍五入后的展示分数判定：最高与第二高分差不超过 8 分，增加“双重魅力”；分差超过 20 分，增加“特质鲜明”；三个分数均在 30—70（含边界），增加“均衡型气质”。

标签不改变主结果。允许条件重叠时同时显示；如数量受限，优先级为“特质鲜明”“双重魅力”“均衡型气质”。

### 4 隐藏彩蛋

彩蛋名称：NPC伪装者：你才是隐藏的主角。

同时满足以下全部条件时触发：

- Q1 = D。
- Q9 = A。
- Q18 = C。
- Q4、Q8、Q13、Q17 四题中至少三题选择 C。

彩蛋检测独立于计分：上述答案仍按照正常映射计入 P/G/M，彩蛋本身不加分、不扣分。仍然计算和保存正常主结果、三维分数及附加标签，另存 `easterEgg=true`。前端主展示切换为彩蛋主题，雷达图继续使用真实分数。彩蛋触发条件不在普通用户页面提前公开。

## 六 结果页和分享要求

### 1 结果页结构

从上到下依次呈现：

1. 结果揭晓：人格插画、结果名称，以及“你的第一印象倾向是”等说明。
2. 人格标签与一句话评语，内容来自附录。
3. 三维画像：三轴雷达图和亲和感、气场感、神秘感的具体分数。
4. 详细分析：采用短段落排版，完整保留原文案含义。
5. 三个典型印象：使用清晰的小模块呈现，不夸大确定性。
6. 成长建议和总结语。
7. 操作区：“生成分享海报”“复制分享链接”“重新测试”。
8. 测试属性和隐私说明。

三种结果使用统一布局并更换主题色和插画。隐藏彩蛋使用黑金与暗紫主题、特殊徽章和独立文案；其典型印象可由彩蛋已有标签和分析概括，保持文案来源清楚。

### 2 雷达图

使用 P/G/M 三轴，固定范围 0—100，刻度 0/20/40/60/80/100。图形与文字必须来自同一份计算结果。三种主题只改变配色，不能改变轴范围、评分或刻度。

图表下始终提供文字分数，单维度为 0、图形退化为线或点时也能读懂。展示“低分只表示该特质在本次选择中较少体现”。动效从中心向外展开，支持减少动态效果。

### 3 海报和公开分享

点击“生成分享海报”后弹出预览，支持保存 PNG。建议生成 1080×1440 的竖版海报；使用相应结果配色，包含测试名称、结果称号、插画、三个重点标签、一句话评语、简版维度分数、测试入口二维码和简短娱乐属性说明。按手机实际阅读尺寸设计字号，不能将整张长结果页缩小成海报。

海报与链接由用户主动创建。公开分享页只显示结果摘要，不提供原始逐题答案、完整会话信息或管理数据。公开 token 使用不可猜测的随机值，可由本人撤销；个人完整结果仍需校验会话所有权。二维码和分享链接使用配置后的真实站点域名。

分享文案支持根据结果替换称号，例如：“我测出的第一印象是「人间小太阳」！你们觉得准吗？”彩蛋使用独立称号。

在支持的浏览器中调用系统分享；其他情况提供复制链接和保存图片。兼容微信内置浏览器的长按保存提示。图片生成失败、权限受限和复制失败时显示可操作的重试或替代入口。

埋点区分分享按钮点击、链接创建、海报生成成功和分享带来的访问。只有真实成功回调才能记录相应成功事件，不能把按钮点击宣称为已经分享。

## 七 管理后台要求

后台使用与前台一致的品牌色，但布局以高效表格和表单为主。桌面为左侧导航、顶部操作栏和右侧内容区；窄屏可以折叠菜单，表格允许横向滚动。

### 1 登录和权限

后台需要真实管理员登录、退出、登录状态过期处理和服务端权限检查。角色建议分为管理员和内容运营：管理员可以发布规则、管理权限和导出数据；运营可以编辑内容草稿、查看汇总。初始管理员通过环境配置或初始化命令创建，不在前端写入账号密码。

### 2 数据总览

展示开始次数、完成次数、完成率、平均答题时长、三种普通结果占比、彩蛋触发率、结果停留时间、海报生成量及分享回流访问。支持日期和版本筛选。所有卡片、图表均来自真实数据；暂无数据时显示空状态。

指标口径：以测试会话去重，完成率为所选开始时间范围内会话的已完成数除以开始数；匿名访问不把会话直接称为准确的独立人数。跨天完成仍归入该开始会话的统计队列，并标明统计截止时间。

为执行“彩蛋单独统计，不计入三种主结果占比”，默认三种普通结果占比分母为非彩蛋的有效完成会话数，分子为其中各正常主结果会话数；彩蛋触发率为彩蛋有效完成会话数除以全部有效完成会话数。每条彩蛋记录仍保存正常主结果，以便另外分析，默认普通结果图不混入该部分。

原文档的三种结果各 25%—40% 仅作为观察参考，不能设置强制配额或通过随机改分来平衡分布。

### 3 题库和选项管理

支持查看、新建、编辑、排序、停用题目，以及管理题干、四个选项、评分映射和状态。改动先进入草稿，发布的 V1 必须正好 18 道启用题，每题四个合法选项，并覆盖 P/G/M 三个维度。

题目 ID 与选项 ID 是稳定业务标识，显示顺序独立存储。同分规则及彩蛋引用这些稳定 ID。V1 初始化时 A/B/C/D 与附录一致；管理员重排题目或选项时，不可因界面位置变化误改原有规则引用。涉及规则含义的修改，需通过新版本预览和校验后发布。

已发布内容不直接原地覆盖。已有答题会话和历史结果继续使用绑定的配置快照。

### 4 结果管理

管理三个主结果和一个彩蛋的名称、标签、一句话评语、详细分析、典型印象、成长建议、总结语、主题色和插画。提供移动端结果预览和海报预览，编辑后可保存草稿并发布新内容版本。

### 5 规则与版本管理

统一配置评分映射、同分规则、附加标签和彩蛋条件。提供版本号、修改说明、草稿预览、规则模拟器、发布和历史回滚。规则模拟器输入 18 个答案后显示分数、同分处理路径、主结果和彩蛋标记。

发布前自动校验题数、选项数、映射完整性、引用有效性和唯一结果判定。回滚只影响后续新建会话，历史记录保持可追溯。

### 6 答题记录和分析

按日期、版本、结果类型和彩蛋标记筛选，查看会话、逐题答案、原始分、展示分数、正常结果、彩蛋状态、开始与完成时间。记录列表不展示不必要的个人信息，详细答案仅授权管理员可见。

分析包含每题选项比例、各维度平均分、完成时长和可用的流失题位置。提供经权限控制的 CSV 导出，并处理 CSV 公式注入风险。关键编辑、发布、回滚和导出写入操作日志。

删除题目等操作对历史版本采用归档或软删除，操作前说明影响；不能破坏既有结果重现。

## 八 数据和技术实现建议

推荐 Next.js App Router + TypeScript + Tailwind CSS。图表使用 ECharts 或同等成熟库；海报使用 html-to-image 或等效实现，二维码使用可靠组件。后端使用框架服务端接口，数据持久化建议 PostgreSQL + Prisma。选用适配当前框架版本的成熟认证方案，输入通过统一 schema 校验。

数据库至少包含：

- `TestVersion`：题库、规则和结果内容版本，状态及发布信息。
- `Question` / `Option`：稳定 ID、正文、显示顺序、维度映射和状态，可绑定版本快照。
- `ResultTemplate`：三个正常结果和彩蛋的文案、插画和配色。
- `TestSession`：匿名会话标识、绑定版本、开始时间和完成状态。
- `Answer`：会话、题目 ID、选项 ID、更新时间。
- `TestResult`：三维原始分、展示分数、正常主结果、彩蛋标记、附加标签、提交时间。
- `Share`：公开 token、所属结果、公开字段及撤销状态。
- `AnalyticsEvent`：必要的事件、时间、版本与来源信息。
- `AdminUser` / `AuditLog`：管理员和关键操作记录。

关键接口包括：创建测试会话、读取该版本题库、保存答案、幂等提交、读取本人结果、创建/撤销公开分享、读取公开摘要，以及受保护的管理接口。

服务端只接受答案和必要会话标识，不信任客户端提交的最终分数、称号和彩蛋标记。提交使用事务及会话唯一结果约束，结果 ID 不作为读取私人数据的唯一凭据。

使用必要的输入校验、登录保护、请求频率限制和安全的会话 cookie。收集范围限于运行测试和统计所需信息，用户能够清除本地草稿、删除本人的结果并撤销公开链接；保留期限和说明保持一致。管理员导出与读取详细答案需要独立权限。

提供 `.env.example`，列明数据库、认证密钥、站点域名和初始化管理员所需配置。不要在交付物中包含真实密钥。

页面包括加载、空数据、网络失败、结果不存在、链接已撤销、版本失效和无权限状态。分享页设置适当的标题、描述和分享预览图；个人结果与后台避免被搜索引擎收录。

## 九 开发顺序和验收标准

使用自动化测试覆盖以下核心行为：

1. 18 道题、每题四个选项、固定顺序；普通用户看不到维度代码。
2. 前后切题、刷新和修改答案均正确保存，缺题或非法选项不能提交。
3. 每维度 0—18、原始分合计 18；展示分数按除以 18 换算，雷达图与数字相同。
4. P/G/M 分别严格最高、三种两维并列、指定题投票同票、三维完全同分均正确返回唯一结果。
5. 彩蛋全部满足才触发；逐项去掉必要条件时不触发；彩蛋不改变正常计分和后台正常结果。
6. 同一会话重复提交不会重复生成结果或累计完成人数；失败重试可恢复。
7. 普通访客不能读取他人的完整结果或管理接口；公开分享页只暴露限定摘要；撤销链接后不能继续读取。
8. 版本发布和回滚不改变进行中的会话及历史结果；排序调整不破坏稳定 ID 引用。
9. 三种普通结果和一个彩蛋均能生成可读海报，二维码可用；分享与统计按定义去重和分类。
10. 在手机、桌面和微信内置浏览器环境检查文字、按钮、图表、海报和错误提示；窄屏没有意外横向溢出。
